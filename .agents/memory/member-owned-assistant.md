---
name: Member-owned assistant scope and release consent
description: Product boundaries and the owner's approval process for external AI assistance.
---

Members bring their own AI. PayGate provides member-authorized access, not a hosted model, another chatbot, or an assistant password login. The approved first version reads permitted gate context and proposes private profile/wishlist changes. Publication, sending, gate progression, spending, and booking remain under explicit member control.

**Why:** The owner wants members' existing assistants to complete agreed tasks without losing member consent or the site's gate protections.

**How to apply:** Expand tasks only with explicit scope approval. Preserve the original five-input, private-draft-and-Accept setup; this assistant-management pilot starts after initial acceptance.

Do not publish or make this feature publicly available until the Agent tests it, the owner tests it, they verify it together, and the owner explicitly accepts it.

**Why:** The owner said: “you test. i test. we test. then after full test and acceptance then publish and make it available.”

**How to apply:** Report development verification honestly and give the owner a concrete testing checklist. An automated pass is not owner acceptance or permission to publish.

Update the site, FAQ, and instructions for setting up both the PayGate side and the member's AI side with this feature.

**Why:** The owner repeated: “as always update site, faq, how to set this up on both sides (site and members AI)”.

**How to apply:** Keep setup instructions visible on the site, not just in repository documentation or chat. Distinguish verified client capabilities from an actual owner-tested connection.
