---
name: Full-intent delivery
description: Andrew expects requested work to be completed end-to-end and verified before it is called done.
---

When Andrew asks for something, complete the full intent end-to-end. Do not stop at a partial implementation when the requested outcome requires connected UI, API, data, routing, content, or deployment-readiness work.

Verify that the outcome works as intended before calling it done. Surface gaps, limitations, and unverified paths clearly instead of declaring completion early.

**Example:** FAQ content in the app is not done until `/faq` is crawlable and exposes real HTML title, H1, and Q&A content for search.

**Why:** Andrew wants the requested user outcome, not only an isolated code change, and relies on the agent to identify and report remaining gaps.

**How to apply:** Re-read the request before finishing, check every explicit requirement, and verify the complete path at a cost proportional to what changed.
